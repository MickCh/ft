# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`fxt` (File Transformer) is a CLI tool for transforming text files: selecting or deleting row/column ranges, reordering rows (sort/tac/shuffle), content filtering (`--grep`, repeatable with `--all`; `--min-fields`, `--max-len`; with `grep`-like exit codes and `--quiet`; `-P` for backreferences and lookaround in every regex), deduplication (`--unique`), case/whitespace transforms (`--upper`/`--lower`/`--title-case`/`--squeeze`/`--trim`), base64/hex/url (`--encode`/`--decode`), tabs and spaces (`--expand`/`--unexpand`), reversing (`--reverse-chars`), row numbering (`--number`), padding (`--pad-left`/`--pad-right`), line wrapping (`--wrap`), splitting a row into many (`--split-on`) and joining them back (`--join`), dropping emptied lines (`--drop-empty`), summaries (`--count`/`--sum`/`--avg`/`--min`/`--max`/`--median`/`--distinct`/`--first`/`--last`, optionally per `--group-by`), input and output in other encodings (`--encoding`/`--output-encoding`, `--lossy` to repair invalid input), rows addressed by content (`--from`/`--to`, like `sed '/A/,/B/'`), find/replace within a column range, and in-place editing of one or many files (`--backup`, `--dry-run`). Row and column ranges support lists and open-ended bounds; rows also take end-relative (`~N`) ones. Column lists keep their order, so they can permute columns; column ranges can address delimited fields (`--fields`, quote-aware with `--quoted`) or grapheme clusters (`--graphemes`). It is also a learning project for idiomatic Rust — code quality and design matter as much as features.

## Commands

```bash
cargo build                     # build
cargo test                      # run all tests
cargo test test_line_replace    # run a single test by name
cargo clippy --all-targets -- -D warnings   # lint (CI fails on any warning)
cargo bench                     # criterion benchmarks of the engine (benches/engine.rs)
cargo bench -- csv              # only the matching cases
cargo fmt                       # format (rustfmt.toml: chain_width 40)
cargo run -- --help             # run the CLI
cargo run -- -R 1-5 -C 2-4 -f foo -r bar input.txt   # example invocation
cargo run -- -F , -C 2-3 data.csv                    # field (delimiter) mode
cargo run -- -R '~10-~1' input.txt                   # end-relative rows (tail)
```

CI (`.github/workflows/rust.yml`) runs `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo build` and `cargo test` on pushes/PRs to `main`, on Linux and Windows.

## Architecture

Library crate (`src/lib.rs`) plus a thin binary (`src/main.rs`). Flow: argv → validated `Config` → composition (`compose::build_processor`) → streaming processor. Only `main.rs` touches the filesystem; the processor works on injected `BufRead`/`Write`, so tests run against in-memory `Cursor`/`Vec<u8>`. Input comes from any number of files and/or stdin (`Config.inputs: Vec<Input>`, `Input::Stdin | Input::File`; never empty, since no argument means stdin).

- `src/main.rs` — `--completions <shell>` (`clap_complete`) and `--man` (`clap_mangen`) are answered straight from the `ArgMatches`, before any `Config` is built (clap makes them exclusive). Otherwise three paths: `run_streaming` (file or stdout; reads every input as one stream via `Read::chain`, like `cat`, and rejects an `--output` that aliases *any* input file, which `File::create` would otherwise truncate before the first read), `run_in_place` (`--in-place`, once per input file so each gets its own row numbering — the batch edit; a file named twice is edited once, deduplicated by canonicalized path; resolves symlinks so the link's target is edited (`resolve`: `canonicalize`, with a verbatim Windows path given back in its ordinary form by `simplified`, so no `\\?\` reaches messages or the sibling file names), then writes to a `.<name>.fxt-<pid>.tmp` sibling — opened with `create_new` so a planted file or symlink at that name is refused — synced to disk and atomically `rename`d over the input, cleaning up the temp file on any error; `--backup <suffix>` copies the original aside just before the swap; a non-empty file the selection took no row of is not written back when the selection drops unselected rows (`leaves_nothing`, `Config::drops_unselected`), since it would come out empty) and `report_changes` (`--dry-run`, which writes nothing: `CompareWriter` is a `Write` that compares the result against the original's bytes as they stream by — leftover bytes in the original count as a difference — so each file is reported as "would change" or "unchanged"). `--in-place` requires file inputs (stdin among them is rejected) and conflicts with `--output`. Every input is opened through `encoding::open` (`--encoding`, else UTF-8; a BOM overrides both), which takes its BOM off and decodes it to UTF-8 before the inputs are chained. Streaming output is encoded into `--output-encoding` (else UTF-8) behind its `BufWriter` and carries no BOM; `run_in_place` and `report_changes` encode into `--output-encoding` or else the file's own encoding, and write its BOM back (`bom_of` that encoding). A `BrokenPipe` while writing (e.g. piping into `head`) exits successfully instead of reporting an error. Exit codes follow `grep`: 0 matched, 1 `--grep` matched nothing, 2 failed — `run` returns a `RunOutcome { matched }` from the engine, which `main` turns into a `Verdict` (without `--grep` nothing can fail to match, so a plain transformation always exits 0). `--quiet` writes to `io::sink()` and sets `FileProcessor::stop_when_matched`, so the engine stops reading at the first match.
- `src/encoding.rs` — text encodings at the edges, so the engine stays UTF-8 only. `open(reader, declared, malformed)` reads up to three bytes to sniff a BOM (`Encoding::for_bom`; bytes that are no mark are put back in front), takes it off and returns a `SourceEncoding { encoding, bom }` plus a `Decoded` reader: UTF-8 passes straight through (the engine validates it row by row), anything else goes through `DecodeReader` (`encoding_rs`; malformed input is an error under `Malformed::Fail`, U+FFFD under `Malformed::Replace` — `--lossy`, via `Config::on_malformed`). `EncodeWriter` does the reverse (UTF-16 by hand, since `encoding_rs` only decodes it), keeping the start of a character a write ended inside for the next one, and fails on an unmappable character. `bom_of` gives an encoding's mark (none for legacy ones); `can_encode` rejects write-less encodings like `replacement`.
- `src/cli_args/` — everything between argv and a valid `Config`:
  - `cli.rs` — clap `Command` definition (name/version come from `crate_name!`/`crate_version!`) and range/delimiter parsing. Rows parse into a `RangeSpec` (comma-separated list of parts; each bound is `FromStart`/`FromEnd`, the latter written `~N`); columns parse into a `ColumnList` (comma-separated too, order preserved) and reject `~`. Same-side inverted ranges are rejected here; mixed-bound inversion is only detectable after resolution.
  - `config.rs` — immutable `Config` built via `TryFrom<ArgMatches>`, which validates cross-argument rules (`--replace` requires `--find` and their counts must match; replace/delete are mutually exclusive; delete needs a row/column range or `--grep`; `--ignore-case` needs a pattern; `--in-place` needs file inputs, never stdin). `rows: Option<RangeSpec>`, `cols: Option<ColumnList>`, `sort_key`/`unique_key`/`grep_key: Option<ColumnList>` (per-operation column ranges, falling back to `cols`), `output_delimiter: Option<String>`, `reorder: Option<ReorderMode>` (sort/tac/shuffle as one enum, so the flags' mutual exclusivity is structural), `replacements: Vec<Replacement>` (each `--find` pre-paired with its `--replace`; `FindPattern` is a literal or a pre-compiled `Pattern`; `grep`, `from_pattern`/`to_pattern` are compiled up front too, in the syntax `-P` picks). Option groups live in substructs: `summary: SummarySpec` (`--count`/`--sum`/`--avg`/`--min`/`--max`/`--median`/`--distinct`/`--first`/`--last`/`--group-by`) and `in_place: Option<InPlace>` (`backup`, `dry_run` — representable only with `--in-place`). `rows_or_full()`/`cols_or_full()` supply the `1..=usize::MAX` fallback; `col_span()`/`span_for()` return a `ColumnSpan` (chars, graphemes under `--graphemes`, or fields when `--fields` is set) built by the shared `span_of()`; whether a bare `--cols` selects (cuts) columns is decided in `compose` (see `ColumnClaims`).
  - `config_error.rs` — `ConfigError` enum with `Display` for user-facing validation messages.
- `src/compose.rs` — the composition layer: `build_processor(&Config)` assembles the `FileProcessor` (row mode, reordering with its column key, row predicate, the summary reducer, and the transform pipeline in the order delete-cols → decode → find/replace pairs → upper → lower → title-case → expand/unexpand → squeeze → trim → reverse-chars → pad → encode → split-on → wrap → drop-empty, with a bare-select prepended when nothing claimed `--cols`; the column-scoped transforms run first, wrapping cuts the finished line, and dropping empties sees what the line became — plus the `outgoing` pipeline, which a line goes through after `--unique`: a rejoin of every field with `--output-delimiter` when no bare selection already did that (and no summary takes the rows), then `--number`, so numbering counts what actually goes out). `ColumnClaims` hands out the shared `--cols` span: an operation takes it by *claiming* it (an operation with its own `--sort-key`/`--unique-key`/`--grep-key` claims nothing), and only a `--cols` no operation claimed becomes a bare column selection — taking the span is what registers the claim, so a new column-scoped operation cannot forget to. All knowledge of how CLI options map onto engine parts lives here, so the engine modules (`transform`, `predicate`, `file_processor`) never depend on `cli_args`.
- `src/columns.rs` — `ColumnList` (column parts as written *plus* their normalized `RangeSet`: reading honours the written order, writing needs sorted, disjoint parts) and `ColumnSpan` (`Chars(ColumnList)`, `Graphemes(ColumnList)` — `--graphemes`, resolved per line to the char ranges its clusters occupy (`resolve_graphemes`, borrowing on ASCII without CRLF), so the char helpers serve it unchanged — or `Fields(FieldSpan)`, the latter carrying delimiter, output delimiter, `quoted` and the field list). `field_positions` splits a line into its fields once per resolution — walking bytes, not chars (a delimiter or quote can only start on a char boundary), and stopping once the fields a span needs plus one are known (`fields_needed`), since that one more tells whether a field follows — quote-aware under `--quoted`, where a delimiter inside `"…"` does not split and a doubled quote escapes one; a field keeps its quotes, so a projection re-joins into valid CSV; `select_value` is the numeric view, which unquotes each field (`"10"` → `10`), and `select_canonical` the key view for `--group-by`: each value re-quoted only where CSV needs it, so `"a"` and `a` meet in one key while distinct field lists cannot. `SplitLine` is a line split once for several spans to read (`select_value_in`/`select_canonical_in`) — a summary's key and aggregates share it; it splits as far as the furthest span needs, and a span with other field settings or reaching further splits for itself, so sharing never changes an answer (a property test holds it to that). `read_ranges(line)` / `write_ranges(line)` / `delete_ranges(line)` resolve a span to the 1-based char ranges it occupies on a concrete line (as `SpanRanges`: borrowed in char mode, else inline `Ranges` — a `SmallVec` — so no line allocates for them; field positions use `Ranges` too), so field mode reuses the char-indexed helpers. Reading keeps the written order (`-C 3,1,2` permutes) and drops field parts the line does not have; writing normalizes first, which is what makes `-C 2,3` delete exactly what `-C 2-3` does; in field mode `write_ranges` then resolves every field of the span on its own (an empty one as an inverted range), so a rewriting transform never reaches across a delimiter, while `delete_ranges` keeps a stretch per part. Delete resolves to swallow one adjacent delimiter, like `cut`; `cell_ranges(line)` resolves to *cells* instead — in field mode each field of the span on its own, an empty one as the inverted range `n..=n-1` — for a transform that writes into every field separately (padding, via `text::map_cells`, which can also write into an empty cell; an empty line is one empty cell to a char or grapheme span starting at column 1); `joiner()` is what rejoins selected fields (`--output-delimiter`, else the input delimiter; `keyed()` drops the output delimiter, which every sort, unique and grep key span gets through `compose::ColumnClaims::key_or_cols`, so keys compare the fields as read; under `--quoted` a rejoin with a new delimiter quotes a field that holds it, `requoted`); with an output delimiter that differs from the input one, reading resolves each field of a part on its own (`read_parts`), so the joiner stands between every two fields, not only between parts.
- `src/records.rs` — `Records`: rows as the engine reads them. A line is a row; under `--quoted` (`FileProcessor::quoted_records`) a line with an odd number of `"` opens a field that the following lines continue, so they are joined (terminators included) into one record, which is the row — `--rows`, `--number`, `--count` and error messages count records. Works on bytes (`"` is ASCII), borrows a plain line and allocates only for a multi-line record; `finish` fails on a quote never closed.
- `src/ranges.rs` — `RangeSet` (normalized, merged, possibly non-contiguous absolute ranges: `contains`, `parts`; also reused by `ColumnList` to normalize columns) and `RangeSpec` (row ranges as written, possibly end-relative). `RangeSpec::is_absolute()` says whether it can resolve without the line count; `resolve(total)` maps every `RangeBound` to an absolute `RangeSet`, dropping empty parts.
- `src/transform.rs` — `LineTransform` trait and its implementations (`SelectColumns` (answers `LineOutcome::Slice` when the selection is one piece of the line, so it is narrowed rather than copied), `DeleteColumns`, `MapColumns` (a boxed mapping closure that writes what a range becomes into the rebuilt line, `Fn(&str, &mut String)`, with ASCII shortcuts; a line it leaves as it was is `Keep`) with upper/lower/trim/title-case/squeeze/expand/unexpand/reverse constructors, `ReplaceInColumns`, `ReplaceInColumnsIgnoreCase` (both return `Keep` for a line without the literal, valid because a literal has no anchors), `RegexReplaceInColumns`, `PadColumns` (`--pad-left`/`--pad-right`, writing into each *cell*), `CodecColumns` (`--encode`/`--decode`, per cell too; decoding fails on invalid input and on non-UTF-8 bytes unless lossy), `NumberLines`, `SplitLines`, `WrapLines`, `DropEmpty`). A transform is **not 1:1**: it returns a `LineOutcome` (`Keep` / `Replace` / `Slice` / `Expand` / `Drop`), so one input line may become several (`--wrap`, `--split-on`) or none (`--drop-empty`). `apply` takes `&mut self`, so a transform may also carry state — `NumberLines` (`--number`) counts the rows it emits, which is why it sits in `FileProcessor::outgoing` (after `--unique`) rather than in the main pipeline, and conflicts with reordering. `MapColumns` covers every whole-span text mapping (upper/lower/trim/title-case/squeeze) through one constructor each, so those need no new type at all. `Pipeline` owns the transforms and folds a line through them into `Lines` (`One(Cow)` — borrowed while untouched — or `Several(Vec<String>)`, empty once dropped), running every later transform on every expanded line. A new per-line operation is a new transform here, not a new branch in the processing loop. Transforms take an `impl Into<ColumnSpan>` and know nothing about the CLI layer.
- `src/pattern.rs` — `Pattern` (text) and `BytePattern` (bytes, for `--from`/`--to`): each `Linear` (`regex`, the default) or `Backtracking` (`fancy-regex`, `-P`: backreferences and lookaround; bytes in `BytesMode::UnicodeBytes`), picked by `Syntax` when `Config` compiles them. `is_match`/`replace_all` return `io::Result`, since backtracking can run out — which is why `LinePredicate::matches`, `LineTransform::apply` (and so `Pipeline::apply`) and `PatternRange::admits` are fallible, and why `text::try_map_ranges` exists. Literal `--find`s stay on `regex` internally.
- `src/pattern_range.rs` — `PatternRange` (`--from`/`--to`): rows addressed by content, which cannot resolve up front like a `RangeSpec`, so it is stateful — `admits(line)` must be told every line in order (also those outside `--rows`) and answers for that one. `sed '/A/,/B/'` semantics: inclusive, the end looked for from the line after the start, every block selected; with no start it opens once at line 1 and may close there (`sed 0,/B/`). Matched as `regex::bytes` against the line without its terminator (`text::without_line_terminator`), so rows outside a block are never required to be UTF-8. `Config::filters_by_content()` (`--grep`/`--from`/`--to`/`--min-fields`/`--max-len`) is what the exit code and `--quiet` key on; `--ignore-case` needs a pattern among them (`has_patterns`).
- `src/predicate.rs` — `LinePredicate` trait and its implementations: `GrepPredicate` (`--grep`/`--invert`, scoped to the column span; several patterns match any of them, or all with `--all`), `MinFields` (`--min-fields`), `MaxLength` (`--max-len`) and `AllOf`, which `compose::build_predicate` uses to join whatever filters are given. Selection mode drops non-matching lines; delete mode deletes matching ones.
- `src/reduce.rs` — the third engine abstraction, next to `LineTransform` and `LinePredicate`: a `LineReducer` consumes the processed lines (`accept`, which is handed the writer so a reducer that can already say something need not hoard the input) and writes what is left at EOF (`finish`) *instead of* the lines. `Join` (`--join`, like `paste -s`) streams: each row goes out as it arrives, with the separator in front of all but the first. `Summarize` implements `--count`/`--sum`/`--avg`/`--min`/`--max`/`--median`/`--distinct`/`--first`/`--last` (an `Aggregate` each, with its own `ColumnSpan`; the numeric ones read `select_value`, the text ones — distinct, first, last — `select_canonical`; a median keeps every value and halves exactly), keyed by `--group-by` (via `select_canonical`) and printed in first-seen key order (`Groups`: a `Vec` alongside the `HashMap`, so the hash map cannot shuffle the output). Each line is split once (`SplitLine`) for the key and every aggregate, and each distinct numeric span is read and parsed once (`NumberReadings`), however many aggregates share it. A value that does not parse as a number takes no part in a statistic; values are read with `ColumnSpan::select_value` (unquoted under `--quoted`) and accumulated as `Number`, so integer sums stay exact. Reducers see the lines that survive the row range, the predicate, the pipeline and `--unique`, so `--unique --count` counts distinct rows; reordered lines drain through the same `output` path once their order is settled, so a reducer sees them in reordered order (`--sort --join` folds sorted). Reducers conflict with `--delete` and `--number`, which would have nothing to act on.
- `src/number.rs` — `Number` (`Int(i128)` | `Float(f64)`, never `NaN`): the parsed value for numeric sort keys and summaries. Integers stay exact (2^53 + 1 is not 2^53), int/float comparison is exact too (`cmp_int_float`), and `-0.0 == 0.0`, so `Ord` is total — the sort relies on it. `Add` stays integer until it overflows.
- `src/case.rs` — `push_titlecase`: titlecase, which `std` lacks — the uppercase, except for the 135 chars (ligatures, digraphs, `ß`, Greek with iota subscript) a table generated from Unicode's titlecase mappings lists (`ﬁ` → `Fi`, `ǆ` → `ǅ`).
- `src/codec.rs` — `Codec` (`Base64` / `Hex` / `Url`): `encode(bytes) -> String` and `decode(text) -> Result<Vec<u8>, DecodeError>`, by hand; a property holds every codec to decoding what it encodes.
- `src/text.rs` — pure char-indexed helpers (`select_columns` for one range; `select_ranges`, `remove_ranges`, `map_ranges`, `replace_in_ranges` for several; `split_line_terminator`), all resolving a char range to byte offsets in one pass (no per-line `Vec<char>`; on an ASCII line `byte_range` maps columns to bytes directly). `select_ranges` reads the parts in the order given (returning a `Cow`, borrowed for a single part) and joins them; the writing helpers share `rewrite_ranges`, which rebuilds the line left to right (each helper writes its range's replacement straight into the result — `map_ranges` and `map_cells` take a mapping that writes, too — so no range gets a string of its own) and therefore expects ascending, non-overlapping ranges. All UTF-8 edge-case tests live here.
- `src/file_processor.rs` — the engine: `FileProcessor` is a plain struct assembled field by field in `compose` (`RowMode` encodes the three valid row treatments: `Select`, `DeleteSelected`, `EditSelected` — the last for `-d -C` and `--keep-others`). `run` takes `self` by value, because a reducer accumulates into itself and a processor is built fresh per input anyway. `run<R: BufRead, W: Write>`: when `rows.is_absolute()` it streams line by line (`bstr::for_byte_line_with_terminator`, through `Records`) resolving rows against `usize::MAX`; when every part starts from the end (`RangeSpec::tail_len`: `~10-`, `~5-~2`) it keeps a ring (`VecDeque<Vec<u8>>`, slots reused) of the last N rows — a row leaving the ring is processed as an unselected row right away, so the pattern range still sees it in order and the row modes that keep such rows write it — and resolves against the line count at EOF; otherwise (`2-~2`) it buffers the whole input first (back to back in one `Vec<u8>`, each row remembered by its end), then resolves rows against the real line count. A property test in `compose` holds the ring to what resolving the whole input selects. Applies row selection (`--rows` intersected with the `PatternRange`, which is advanced on every line first), the row predicate, the transform pipeline, `--unique` and the `outgoing` pipeline (`--number`), with the terminator split off and re-attached (original terminators, including CRLF, preserved). A processed row must be UTF-8; under `--lossy` (`FileProcessor::lossy`) it is repaired with `from_utf8_lossy` instead, and a repaired row the pipeline returned untouched goes out as its raw bytes when it streams straight to the writer (no reordering, no reducer), so lossy mode rewrites no more than the edit does. Because a transform may expand one line into several, `emit` runs per produced line, and the terminator an unterminated line owes is written lazily (`RunState::needs_separator`): only once something actually follows it, so the last line written stays unterminated whether it was reordered, expanded or both. That terminator is never the platform's: `RunState::ending` (a `reduce::InputEnding`) follows the terminator of every row read (the last one seen, `\n` before any) and whether the input's last line had one, and it is handed to `LineReducer::finish` too, so `--join` ends its row as the input ended and summaries terminate theirs in the input's style.

Key processing concept: transforms stream (each line written immediately), but reordering is *sequence-breaking* — lines inside the row range are buffered in `RunState::reorder_buffer` (a `LineBuffer`: every line's text back to back in one `String`, plus a `Line { start, end, terminator }` record each, so reordering moves only the records and the allocation is reused for the next run of rows) and flushed before any kept out-of-range line is written and at EOF, so each contiguous run of selected rows reorders in place. `Reorder` unifies the three reordering ops: `Sort` (via `SortSpec`: key `ColumnSpan`, `--numeric` via an `Option<Number>` key read with `select_value` — unparseable and `NaN` keys are `None` and sort first, `--reverse` by flipping the comparison; each key is computed once — a text key borrowed from its line, with its first eight bytes in front as a `u64` (`byte_prefix`) so most comparisons never reach the line — and `sorted_order` sorts keys with their positions, the position breaking ties, which makes the fast unstable sort stable both ways; `permute` then moves each line once), `Tac` (reverse) and `Shuffle` (rand 0.9). `--unique` keys on the column span of the transformed content via a shared `seen_keys` `HashSet` (first wins; post-sort order with `--sort`), read with `select_canonical`, so under `--quoted` it compares values like `--group-by`. Sort keys (text and numeric) are read with `select_value`, unique and group keys with `select_canonical`, so under `--quoted` every key compares field values. All keys use `select_columns` semantics: a span beyond the line yields an empty key, like `cut`. Their spans come from `--sort-key`/`--unique-key` when given, `--cols` otherwise.

All column/row semantics are 1-based inclusive, and column indexing is by `char`, not by byte (by grapheme cluster under `--graphemes`, which also makes `--wrap` use `text::wrap_graphemes`). End-relative rows count `~1` as the last line. Column lists keep their written order for reading operations (select, sort/unique key, `--grep`) and are normalized for writing ones (delete, case/trim, find/replace).

Tests: unit tests live next to the code; `properties` modules (`proptest`) in `columns.rs` and `text.rs` check the splitter, grapheme columns and the char helpers against obviously-right references, and the one in `cli_args/cli.rs` fuzzes the range parsers (no panics, only spec characters accepted, generated specs select what their definition names) — extend them when touching that code, and delete `proptest-regressions/` files that come from deliberately broken code; end-to-end CLI tests in `tests/cli.rs` run the real binary via `env!("CARGO_BIN_EXE_fxt")` — extend those whenever CLI behavior changes.

## Conventions

- Code, comments, docs, commit messages: English only.
- Design goals for this codebase: SOLID principles, the stairway pattern (depend on traits/abstractions, not concrete types, with dependencies pointing "down the stairs"), and idiomatic Rust (prefer `Result` propagation over `unwrap`, iterators over index loops, borrowed types in signatures).
- Tests live in `#[cfg(test)]` modules next to the code and follow a Given/When/Then comment style.
